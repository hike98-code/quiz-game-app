index.html의 퀴즈 데이터를 점검하고, 부족한 카테고리에 문제를 1개 추가하는 일일 유지보수 루틴을 수행해줘.

$ARGUMENTS 형식: "$1" — 예: "hard", "medium", "easy"
- $1 = 추가할 문제의 난이도 (생략 시 자동 판단)
- 유효하지 않은 값이면 오류를 보고하고 중단.

---

## 실행 원칙

각 단계는 순서대로 실행한다.
단계가 실패하면 **즉시 중단**하고, 아래 형식으로 오류를 보고한다:

```
❌ [Step N 실패] 단계명
원인: <오류 내용>
조치: <해결 방법 제안>
```

모든 단계가 성공하면 Step 7에서 상세 보고를 출력한다.

---

## Step 1 — 파일 구조 파악

index.html을 읽어 아래 항목을 확인한다:

- QUESTIONS 배열이 존재하는가?
- 각 문제 객체에 id / category / difficulty / question / options / answer / hint / explanation 필드가 있는가?
- 카테고리 접두사 규칙(WH/SC/GE/GN)이 사용되는가?

**검증**: QUESTIONS 배열이 없거나 필드 구조가 다르면 즉시 중단.
성공 시 출력:
```
✅ Step 1 완료 — 파일 구조 정상
  · 배열명: QUESTIONS
  · 필드: id, category, difficulty, question, options, answer, hint, explanation
  · 카테고리 접두사: WH / SC / GE / GN
```

---

## Step 2 — 현재 문제 개수 및 분포 확인

QUESTIONS 배열에서 아래 수치를 집계한다:

- 전체 문제 수
- 카테고리별 문제 수 (history / science / geo / general)
- 전체 및 카테고리별 난이도 분포 (easy / medium / hard)
- 전체 정답 번호 분포 (1번~4번)

**검증**: 배열이 비어 있으면 즉시 중단.
성공 시 출력:
```
✅ Step 2 완료 — 현황
  · 총 문제 수: N개
  · history N | science N | geo N | general N
  · 난이도: easy N (N%) / medium N (N%) / hard N (N%)
  · 정답 분포: 1번 N / 2번 N / 3번 N / 4번 N
```

---

## Step 3 — 카테고리별 부족 파악 및 추가 대상 결정

아래 기준으로 점수를 계산해 추가 우선순위가 가장 높은 카테고리를 선택한다:

**카테고리 선택 기준** (점수 합산, 높을수록 우선):
- 문제 수가 가장 적은 카테고리: +3점
- 정답 번호 편중이 심한 카테고리 (특정 번호 ≥ 40%): +2점
- 난이도 분포가 권장(easy 30/medium 50/hard 20%)에서 가장 벗어난 카테고리: +1점

**난이도 선택** ($1 인수가 있으면 그 값을 우선 사용):
- 인수가 없으면: 선택된 카테고리에서 권장 비율 대비 가장 부족한 난이도를 자동 선택
- 단, 해당 카테고리의 정답 4번(index 3)이 0개이면 반드시 answer: 3인 문제를 생성

**검증**: 모든 카테고리가 동일 문제 수이고 분포도 동일하면 "추가 불필요" 보고 후 중단.
성공 시 출력:
```
✅ Step 3 완료 — 추가 대상 결정
  · 선택 카테고리: [카테고리명] (사유: ...)
  · 선택 난이도: [난이도] (사유: ...)
  · 목표 answer index: N번 (사유: ...)
```

---

## Step 4 — 중복 체크

Step 3에서 결정한 카테고리·난이도를 바탕으로 신규 문제 초안을 생성한 뒤,
기존 QUESTIONS 배열 전체와 비교해 아래 항목을 확인한다:

1. **question 중복**: 동일하거나 80% 이상 유사한 질문이 있는가?
2. **topic 중복**: 같은 카테고리에서 동일한 핵심 소재(인물/사건/개념)를 다루는 문제가 이미 있는가?
3. **answer 쏠림**: 생성 예정 answer index가 해당 카테고리에서 이미 50% 이상 차지하는가?

**검증**: 중복이 발견되면 주제를 바꿔 문제를 재생성하고 다시 점검한다 (최대 3회).
3회 모두 중복이면 중단하고 오류 보고.
성공 시 출력:
```
✅ Step 4 완료 — 중복 없음
  · question: 중복 없음
  · topic: 중복 없음
  · answer index N번: 해당 카테고리 내 비율 N% (안전)
```

---

## Step 5 — 문제 삽입 및 형식 검증

### 5-A. 삽입 전 자가검증 (4항목)

생성된 문제를 삽입하기 전, 아래 항목을 각각 ✅/⚠️로 판정한다.
⚠️가 하나라도 있으면 문제를 수정한 뒤 재검증한다:

1. **정답 유일성** — 다른 선택지가 정답으로 해석될 여지가 없는가?
2. **최상급 기준** — "가장, 최초, 최대, 최소, 최장, 최단, 최고, 최저, 유일, 처음, 먼저" 포함 시 explanation에 측정 기준이 명시되어 있는가?
3. **시간·범위 명확성** — 변할 수 있는 정보에 기준 시점이 있는가?
4. **사실 신뢰성** — 주류 학설·공인 기준에 부합하며 논란 소지가 없는가?

### 5-B. 삽입

해당 카테고리 블록의 마지막 `},` 바로 뒤에 삽입:

```js
      {
        id: '{PREFIX}-{NNN}',
        category: '{category}',
        difficulty: '{difficulty}',
        question: '...',
        options: ['...', '...', '...', '...'],
        answer: N,
        hint: '...',
        explanation: '...',
      },
```

### 5-C. 삽입 후 검증

삽입 직후 index.html을 다시 읽어 확인:
- 삽입된 ID가 QUESTIONS 배열에 존재하는가?
- options 4개, answer 0~3 범위인가?
- JSON 구조가 깨지지 않았는가? (중괄호·쉼표 누락 여부)

**검증**: 5-C에서 이상이 발견되면 삽입을 되돌리고 중단.
성공 시 출력:
```
✅ Step 5 완료 — 삽입 및 형식 검증 통과
  · 삽입 ID: {PREFIX}-{NNN}
  · 자가검증 4항목: ✅ ✅ ✅ ✅
  · 삽입 후 구조 확인: ✅
```

---

## Step 6 — 전체 데이터 백업

index.html 전체를 읽어 백업 파일을 생성한다.

백업 파일명 규칙: `index.backup.YYYYMMDD.html`
저장 위치: index.html과 동일한 디렉터리

**검증**: 백업 파일이 정상적으로 생성되었는지 확인한다
(index.html과 백업 파일의 줄 수가 일치하는가).
성공 시 출력:
```
✅ Step 6 완료 — 백업 생성
  · 파일명: index.backup.YYYYMMDD.html
  · 원본 줄 수: N줄 / 백업 줄 수: N줄 (일치 ✅)
```

---

```

[Step 4] 중복 체크             ✅

── 추가된 문제 ──────────────────────

  1번: N개 (N%)
  2번: N개 (N%)
  3번: N개 (N%)
  4번: N개 (N%)

── 잔여 개선 과제 ───────────────────
(카테고리·난이도·정답 분포 중 여전히 권장 범위를 벗어난 항목만 표시)

── 백업 ─────────────────────────────

══════════════════════════════════════
```
