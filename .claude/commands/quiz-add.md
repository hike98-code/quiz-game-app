index.html의 QUESTIONS 배열에 새 퀴즈 문제를 1개 추가해줘.

## 입력 파싱

$ARGUMENTS 형식: "$1 $2" — 예: "history easy", "science medium", "geo hard"
- $1 = 카테고리: history | science | geo | general
- $2 = 난이도: easy | medium | hard
- 인수가 없거나 유효하지 않으면 오류 메시지를 출력하고 중단해.

카테고리별 ID 접두사:
- history → WH
- science → SC
- geo → GE
- general → GN

## 실행 순서

### Step 1 — 현황 파악
index.html을 읽어서:
1. 해당 카테고리의 기존 문제 ID 목록을 확인하고, 다음 번호를 결정한다 (예: WH-010이 마지막이면 신규 ID는 WH-011).
2. 해당 카테고리 블록의 마지막 `},` 위치(삽입 지점)를 파악한다.
3. 현재 카테고리의 easy/medium/hard 분포를 출력한다.

### Step 2 — 문제 생성
아래 조건을 모두 만족하는 문제를 1개 창작한다:
- 지정된 카테고리와 난이도에 적합한 주제
- 선택지 4개 (오답 3개는 그럴듯하되 명확히 틀린 것)
- answer는 0-based index (0~3)
- hint: 정답을 직접 노출하지 않고 방향을 안내하는 1~2문장
- explanation: 정답 근거 + 오답이 왜 틀렸는지 간략히 포함, 2~3문장

### Step 3 — 검증 (삽입 전 자가점검)
아래 4개 항목을 각각 ✅/⚠️로 판정하고, ⚠️가 하나라도 있으면 문제를 수정한 뒤 재검증한다:

1. **정답 유일성** — 다른 선택지가 정답으로 해석될 여지가 없는가?
2. **최상급 기준** — "가장, 최초, 최대, 최소, 최장, 최단, 최고, 최저, 유일, 처음, 먼저" 포함 시 explanation에 측정 기준이 명시되어 있는가?
3. **시간·범위 명확성** — 변할 수 있는 정보(인구, 현직, 기록 등)에 기준 시점이 있는가? 지리·분류 범위가 한정되어 있는가?
4. **사실 신뢰성** — 주류 학설·공인 기준에 부합하며 논란 소지가 없는가?

### Step 4 — 삽입
검증을 모두 통과하면 해당 카테고리 블록의 **마지막 문제 닫는 `},` 바로 뒤**에 아래 형식으로 삽입한다:

```js
      {
        id: '{PREFIX}-{NNN}',
        category: '{category}',
        difficulty: '{difficulty}',
        question: '...',
        options: ['...', '...', '...', '...'],
        answer: N,
        hint: '...',
        explanation: '...',
      },
```

### Step 5 — 결과 보고
삽입 후 다음을 출력한다:
1. 삽입된 문제 블록 전체 (코드 블록으로)
2. 검증 결과 4항목 요약 (✅/⚠️)
3. 해당 카테고리의 업데이트된 easy/medium/hard 분포
